<ComponentDescription>AIMessages draws every message of a chat: the question of the user in a bubble, and the answer of the assistant with its reasoning, its text, its tool results and its attached files. Under a finished answer it adds a floating bar of actions, and while the assistant has not written anything yet it shows a running reasoning header.</ComponentDescription>

`AIMessages` works with no props. When you need more control, the same pieces are available as small components that you put together, like blocks. Each one has its own page in the sidebar.

## Setup

Import the package styles once, next to the Shoreline ones:

```tsx
import '@vtex/shoreline/css'
import '@vtex/shoreline-ai/css'
```

Then mount `AIMessages` inside `<AIProvider>`, usually inside the viewport of an [AIThread](/components/ai-thread). The thread gives the list its padding; outside a thread the list has no side padding. Wrap your app with `LocaleProvider` to get the built-in labels in `en-US` or `pt-BR`.

## Usage

The drop-in list needs no props. It draws the user and assistant layouts, groups the reasoning, renders markdown and tool widgets, and adds the actions bar:

```tsx
import { LocaleProvider } from '@vtex/shoreline'
import {
  AIMessages,
  AIProvider,
  AIThread,
  AIThreadViewport,
  type AIProviderProps,
} from '@vtex/shoreline-ai'

function Chat(props: { runtime: AIProviderProps['runtime'] }) {
  return (
    <LocaleProvider locale="en-US">
      <AIProvider runtime={props.runtime}>
        <AIThread>
          <AIThreadViewport>
            <AIMessages />
          </AIThreadViewport>
        </AIThread>
      </AIProvider>
    </LocaleProvider>
  )
}
```

See [AIThread](/components/ai-thread) for the full chat, with the composer.

## How it is built

`AIMessages` renders one `AIMessageUser` or one `AIMessageAssistant` for each message. Pass your own copy of either one as a child to change its layout. Each of them is an `AIMessageRoot` that holds the parts of the message:

```tsx
<AIMessages>
  <AIMessageUser />
  <AIMessageAssistant>
    <AIMessageParts />    {/* text, reasoning, tools and files, in order */}
    <AIMessageActions />  {/* the bar under the answer */}
  </AIMessageAssistant>
</AIMessages>
```

The actions bar is built from smaller parts in the same way:

```tsx
<AIMessageActions>
  <AIMessageAction label="…">…</AIMessageAction>  {/* your actions */}
  <AIMessageCopy />
  <AIMessageDate />
</AIMessageActions>
```

The reasoning panel that `AIMessageParts` draws is its own family, [AIReasoning](/components/ai-reasoning), with its own section in the sidebar.

| Component | What it is |
|-----------|-----------|
| [AIMessageUser](/components/ai-messages/ai-message-user) | The message of the person, as a bubble on the right |
| [AIMessageAssistant](/components/ai-messages/ai-message-assistant) | The answer of the assistant, on the left |
| [AIMessageRoot](/components/ai-messages/ai-message-root) | The container of one message |
| [AIMessageParts](/components/ai-messages/ai-message-parts) | Draws each part of the message and groups the reasoning steps |
| [AIMessageText](/components/ai-messages/ai-message-text) | A text part, as markdown |
| [AIMarkdown](/components/ai-messages/ai-markdown) | Markdown on its own, with no message around it |
| [AIMessageActions](/components/ai-messages/ai-message-actions) | The floating bar under an answer |
| [AIMessageAction](/components/ai-messages/ai-message-action) | A button of the bar, for thumbs or any action of your app |
| [AIMessageCopy](/components/ai-messages/ai-message-copy) | The button that copies the text of the message |
| [AIMessageDate](/components/ai-messages/ai-message-date) | When the message was sent |
| [AIMessageResources](/components/ai-messages/ai-message-resources) | The files and images attached to a message |
| [AIMessagesI18nProvider](/components/ai-messages/ai-messages-i18n-provider) | The labels of message pieces rendered outside `AIMessages` |
| [Hooks](/components/ai-messages/hooks) | `useAIMessage` and the hooks that read messages and the thread |

The reasoning header uses two pieces that also work on their own, anywhere: [AIThinkingIndicator](/components/ai-thinking-indicator), the text loading effect, and [AIWorkingMark](/components/ai-working-mark), the spinning mark.

## Examples

### Reasoning

While the assistant works, its reasoning steps and the tools it calls are collected in one panel that starts closed, as in the first example on this page. `AIMessageParts` draws one panel per reasoning group with the [AIReasoning](/components/ai-reasoning) template; its states, its parts and how to replace the template are on that page.

The mark of the panel is the My Assistant mark. To use the glyph of your app in every mark of the list, pass `workingMark`:

```tsx
<AIMessages workingMark={<IconSparkle />} />
```

The other ways to replace it are on the [AIWorkingMark](/components/ai-working-mark#change-the-glyph) page.

### Actions bar

A finished answer that has text gets an [AIMessageActions](/components/ai-messages/ai-message-actions) bar. With no children it has [AIMessageCopy](/components/ai-messages/ai-message-copy) and then [AIMessageDate](/components/ai-messages/ai-message-date), as in the first example on this page. With children it renders exactly them, in the order you give.

Thumbs and their behavior belong to your app, so the package ships neither. Wrap your own icons in [AIMessageAction](/components/ai-messages/ai-message-action), and keep the vote of each answer keyed by the message id that [`useAIMessage()`](/components/ai-messages/hooks#useaimessage) returns. In the example, press a thumb to vote, press it again to clear the vote, or press the other one to change it:

### Custom parts

`AIMessageParts` accepts a function as `children`. It is called for each part; return a node to replace the default drawing, or `null` to keep it. The example below replaces only the text part. See [AIMessageParts](/components/ai-messages/ai-message-parts#custom-parts) for the arguments of the function.

### Tool widgets

Register a component for a tool with `makeAIToolUI` and mount the result once under the provider. A registered tool is drawn in the message, not in the reasoning panel. With `mode: 'canvas'` the message shows a trigger and the tool opens in `AICanvas`. A function child of `AIMessageParts` that handles the same tool wins over the registered component. To draw a tool inside the reasoning panel instead, see [AIReasoningContent](/components/ai-reasoning/ai-reasoning-content#draw-a-tool-your-way-inside-the-panel).

<Preview name="ai-messages-tool-ui" />

### User bubble

The bubble of the user is only CSS. Its width is capped at `33.75rem`. Change the cap with `--sl-ai-message-user-max-width`:

```css
[data-sl-ai-messages] {
  --sl-ai-message-user-max-width: 28rem;
}
```

See [AIMessageUser](/components/ai-messages/ai-message-user).

## Where a customization lives

| You want to change | Use |
|--------------------|-----|
| A text for the whole chat | `messages` on `AIMessages` |
| The text of one reasoning label | Children of [AIReasoningLabel](/components/ai-reasoning/ai-reasoning-label) |
| The working mark | `workingMark` on `AIMessages`, or see [AIWorkingMark](/components/ai-working-mark#change-the-glyph) |
| The header pieces or their order | The `reasoning` template of `AIMessageParts`; see [AIReasoning](/components/ai-reasoning#custom-template) |
| How one kind of part is drawn | A function child of [AIMessageParts](/components/ai-messages/ai-message-parts#custom-parts) |
| Bar actions | Children of [AIMessageActions](/components/ai-messages/ai-message-actions) |
| The layout of one message | An `AIMessageUser` or `AIMessageAssistant` child of `AIMessages` |
| Language, dates and durations | `LocaleProvider` |
| Spacing around and between messages | The custom properties of [AIThread](/components/ai-thread#layout-and-spacing) |

## Labels and languages

The labels come from a built-in catalog in `en-US` and `pt-BR`, chosen by the `LocaleProvider`. Times, durations and dates follow the same locale and come from `Intl` (en-US "1m 5s", "Nov 12, 2:32 PM"). The pt-BR catalog overrides the formats where the `Intl` default does not match the design ("1m 5s", "12 nov, 14:32"). To change some labels for the whole chat, pass `messages` to `AIMessages`. Unset keys keep the default. To change the text of a single label, pass children to `AIReasoningLabel`:

<Preview name="ai-messages-labels" />

| Id | `en-US` | Where it shows |
|----|---------|----------------|
| `reasoningStreaming` | Thinking… | The label while the reasoning is running |
| `reasoningDone` | Done thinking | The label when it is complete and no duration is known |
| `reasoningDoneIn` | `Thought for {duration}` | The label when the duration is known. `{duration}` comes from `Intl` |
| `copyMessage` | Copy message | The name of the copy button |
| `copied` | Copied! | The name of the copy button for 2 seconds after a copy |
| `messageCopied` | Message copied | Announced to screen readers after a copy |
| `copyCode` | Copy code | Not used yet. It is kept for the code blocks |

To give these labels to message pieces rendered outside `AIMessages`, use [AIMessagesI18nProvider](/components/ai-messages/ai-messages-i18n-provider).

## Long threads

Each message row (`[data-sl-ai-message]`) uses `content-visibility: auto`, so rows that are off screen cost nothing. How that affects the scroll, and how to tune the placeholder height, is on [AIThread](/components/ai-thread#long-conversations).

Because `content-visibility` clips the painting of a row to its box, the row has padding and a negative margin that cancel each other: the content keeps its width and position, and focus rings, the reasoning chevron and the floating actions bar are not clipped by the row. The row box itself extends about `1rem` past the list on each side, so a focus ring at the very edge would still be clipped by an ancestor with `overflow: hidden`, such as the thread viewport. Inside a thread this does not happen: the viewport gives the list `1rem` of padding through `--sl-ai-messages-padding`, also when you wrap `AIMessages` in your own element. If your wrapper pads itself, set `--sl-ai-messages-padding: 0` on it so the padding is not applied twice, and keep about `1rem` of horizontal padding there. Do not override `padding`, `margin` or `box-sizing` on the message row.

## Optional props

<PropsDocs name="ai-messages" />

`AIMessages` also accepts the props of a `div`. Its children can only be one `AIMessageUser` and one `AIMessageAssistant`, used as templates.

## Styling

| Attribute | Region |
|-----------|--------|
| `[data-sl-ai-messages]` | The list. A flex column with `--sl-ai-messages-gap` between messages and the same room below the last one |

| CSS variable | Default | What it changes |
|--------------|---------|-----------------|
| `--sl-ai-message-intrinsic-size` | `5rem` | The placeholder height of a message that was not rendered yet |
| `--sl-ai-messages-gap` | `var(--sl-space-8)` | The gap between messages, and the space below the last one. See [AIThread](/components/ai-thread#layout-and-spacing) |
| `--sl-ai-messages-padding` | `0`; the thread padding inside a thread viewport | The padding of the list. Set it to `0` on a wrapper that pads itself |

The selectors of each piece are on its page.
