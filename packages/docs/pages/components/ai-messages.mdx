# AIMessages

import { Callout } from 'nextra/components'

<Callout type="warning" emoji="⚠️">
  **Experimental.** `@vtex/shoreline-ai` is not published yet and its API can change.
</Callout>

The conversation itself. `AIMessages` draws every message of the thread: the question of the user in a bubble, and the answer of the assistant with its reasoning, its text, its tool results and its attached files. It also gives the answer a floating bar of actions (copy and the date) and shows a running reasoning header while the assistant has not written anything yet.

`AIMessages` works with no props. When you need more control, the same pieces are available as small components that you put together, like blocks.

<Callout type="info">
  The examples on this page run with a mock runtime and a short conversation that is loaded when the example opens, so they work without a backend. In your app, wrap the messages with `<AIProvider>` and a runtime built from your own transport. See the [Runtime guide](/guides/shoreline-ai-runtime).
</Callout>

## Setup

Import the package styles once, next to the Shoreline ones:

```tsx
import '@vtex/shoreline/css'
import '@vtex/shoreline-ai/css'
```

Then mount `AIMessages` inside `<AIProvider>`, usually inside the viewport of an [AIThread](/components/ai-thread). The thread gives the list its padding through `--sl-ai-messages-padding`, also when you wrap the list in your own element; outside a thread the list has no side padding. Wrap your app with `LocaleProvider` to get the built-in labels in `en-US` or `pt-BR`.

## How it is built

`AIMessages` renders one `AIMessageUser` or one `AIMessageAssistant` for each message. You can pass your own copy of each one as a child to change a layout. Each of them is an `AIMessageRoot` that holds the parts of the message:

```tsx
<AIMessages>
  <AIMessageUser />
  <AIMessageAssistant>
    <AIMessageParts />    {/* text, reasoning, tools and files, in order */}
    <AIMessageActions />  {/* the bar under the answer */}
  </AIMessageAssistant>
</AIMessages>
```

| Component | What it is |
|-----------|-----------|
| `AIMessages` | The list. It renders every message with the default user and assistant layouts |
| `AIMessageUser` | The message of the person, as a bubble on the right |
| `AIMessageAssistant` | The answer of the assistant, on the left. With no children it renders `AIMessageParts` and `AIMessageActions`. With children it renders exactly them |
| `AIMessageRoot` | The container of one message. It sets `messageRole` |
| `AIMessageParts` | Draws each part of the message and groups the reasoning steps. Takes a `reasoning` template and a function to draw parts your way. Before the first part it draws the running reasoning header |
| `AIMessageText` | A text part, as markdown |
| `AIMarkdown` | Markdown on its own, with no message around it |
| `AIMessageReasoning` | The connected reasoning panel, for the `reasoning` template of `AIMessageParts` |
| `AIMessageReasoningRoot` | The reasoning panel and its state, for panels you build by hand |
| `AIMessageReasoningHeader` | The 20px row: mark, label, elapsed time and chevron |
| `AIMessageReasoningMark`, `AIMessageReasoningLabel`, `AIMessageReasoningElapsed` | The pieces of the header |
| `AIMessageReasoningTrigger` | The chevron button that opens and closes the panel |
| `AIMessageReasoningContent` | The body of the panel |
| `AIMessageReasoningText` | The text of one reasoning step |
| `AIMessageReasoningToolStep` | A small row for a tool call that has no UI of its own |
| `AIThinkingIndicator` | The text loading effect. Its children shimmer |
| `AIWorkingMark` | The small spinning mark, with a glyph you can replace |
| `AIMessageActions` | The floating bar under an answer. With no children it has copy and the date |
| `AIMessageAction` | A button of the bar. Use it for thumbs or any action of your app |
| `AIMessageCopy` | The button that copies the text of the message |
| `AIMessageDate` | The relative date of the message |
| `AIMessageResources`, `AIMessageResource`, `AIMessageResourceImage`, `AIMessageResourceFile` | The files and images attached to a message |

The package also exports two helpers: `renderDefaultParts`, which draws one part the default way, and `defaultMessageGroupBy`, the rule that decides which parts go into the reasoning panel. `MessageMessagesProvider` gives message pieces their labels, for rendering them outside `AIMessages`, for example in a test.

## Examples

### Reasoning

While the assistant works, its reasoning steps and the tools it calls are collected in one panel that starts closed. The header is one row: a spinning mark, the label, the elapsed time and a chevron. Only the chevron is a button; it opens and closes the body and is named by the label.

| State | Mark | Label | Time | Chevron |
|-------|------|-------|------|---------|
| Running | yes | "Reasoning…", shimmering | "40s", then "1m 5s" | yes |
| Done, with a duration | no | "Reasoning completed in 2m" | no | yes |
| Done, no duration | no | "Reasoning complete" | no | yes |

Times and durations follow the locale of the `LocaleProvider` (en-US "1m 5s", pt-BR "1 min 5 s"). While the reasoning runs, the header counts the seconds itself. When it completes, it shows the runtime duration when there is one, and otherwise the time it counted. A message loaded from history has no duration and reads "Reasoning complete".

The pieces are public, so you can build your own panel with `AIMessageReasoningRoot`. `status` sets the header, `startedAt` is the origin of the elapsed time, and `defaultExpanded` opens the panel from the start. For a panel you control, pass `expanded` and `onExpandedChange`.

<Callout type="info">

</Callout>

#### Before the first part

Every answer is assumed to have reasoning. While a message runs and has no text, reasoning or tool call yet, `AIMessageParts` draws the running header, with no chevron. Only its label is a live region (`role="status"`), so "Reasoning…" is announced once and the ticking elapsed time is not. When the first reasoning part arrives it is the same header: the elapsed time does not reset and the mark does not blink.

If text arrives before any reasoning part, the header disappears. If an unregistered tool call arrives first, it opens a running reasoning group, so the header stays and now has a chevron.

#### The working mark

`AIMessages` has one reasoning shortcut: `workingMark`. It is the glyph of every mark in the list, including the one in the header before the first part, so an app with its own mark does not recompose anything:

```tsx
<AIMessages workingMark={<IconSparkle />} />
```

Without it, the mark is the My Assistant mark. You can override it in three ways: children of `AIWorkingMark`, children of `AIMessageReasoningMark` in a reasoning template, or `workingMark` on `AIMessages` for every mark in the list.

#### The reasoning template

`AIMessageParts` takes a `reasoning` element, the template it draws once per reasoning group. The default is `<AIMessageReasoning />`. Pass your own to change the header, for example its label. `AIMessageReasoning` reads the status, duration and start time of the group, so it only works inside `AIMessageParts`. Inside it, `useAIMessageReasoning()` gives your own parts read-only access to `status`, `expanded` and `duration`.

### Hide the tool steps

By default the panel also lists the tools the assistant called, as small steps. To keep only the reasoning text, set `showReasoningTools={false}` on `AIMessages`, `AIMessageAssistant` or `AIMessageParts`. Open the panel below: the reasoning is there, and the `search_orders` step is not.

<Preview name="ai-messages-hide-tools" />

Tools that you registered with `makeAIToolUI` are not affected. They always show in the message, outside the panel.

### Thinking indicator and working mark

Both are small pieces that you can use anywhere, even outside a message. `AIThinkingIndicator` is the text loading effect: its children shimmer, with a light band that sweeps across the text. It has no default text, no dots and no `role`; set `role="status"` yourself if the text must be announced. `AIWorkingMark` is the spinning mark. It is decorative (`aria-hidden`) and its children replace the glyph.

<Preview name="ai-messages-thinking" />

With `prefers-reduced-motion: reduce` the text stays plain and the mark pulses slowly instead of rotating.

### Actions bar

A finished assistant answer that has text gets an `AIMessageActions` bar. It floats just below the message, takes no height and is always visible. It does not show while the answer runs, for the messages of the user, or for messages with status `incomplete` (for example a cancelled run), so a partial answer cannot be copied.

With no children the bar has `AIMessageCopy` and then `AIMessageDate`. With children it renders exactly them, in the order you give. There are no boolean props to turn pieces on or off: compose the bar. Thumbs and their behavior belong to your app, so the package ships neither. Wrap your own icon (any Shoreline icon or your SVG) in `AIMessageAction`, give it a `label` for its accessible name, and set `aria-pressed` for a pressed state. The bar renders once per answer, so keep per-answer state keyed by the message id that `useAIMessage()` returns, as the example below does.

<Preview name="ai-messages-actions" />

`AIMessageCopy` copies the text parts of the message. No toast is shown: the copy icon turns into a check for 2 seconds, the accessible name becomes "Copied!", and a hidden live region announces "Message copied" to screen readers. Pass `onCopied` to know when it worked, for example to track it.

`AIMessageDate` shows the age of the message ("now", "5m ago", "yesterday") from `createdAt`, or from its `date` prop. It is a `time` element: `dateTime` is the ISO value and `title` is the exact local date and time. Only the "now" form is always visible. Any other date shows when you hover the message or when focus is inside it, so a keyboard user reaches it with <kbd>Tab</kbd>. On devices without hover it is always visible. All the dates share one timer that ticks once a minute. "Yesterday" means the previous calendar day; older dates read "4d ago", then "1mo ago" and "1y ago". With server rendering, the text and the title appear after hydration, in the viewer's timezone.

### Custom parts

`AIMessageParts` accepts a function as `children`. It is called for each part with the part and some context (`index`, `isStreaming`, `placement` and `toolRegistration`). Return a node to replace the default drawing, or return `null` to keep it. The example below replaces only the text part:

<Preview name="ai-messages-parts" />

Prefer `meta.isStreaming` and `meta.placement` over reading the whole thread in a renderer. If you need to wrap the default drawing of a part instead of replacing it, call `renderDefaultParts(part, meta)` and return its result.

### Tool widgets

Register a component for a tool with `makeAIToolUI` and mount the result once under the provider. A registered tool is drawn in the message, not in the reasoning panel. With `mode: 'canvas'` the message shows a trigger and the tool opens in `AICanvas`.

<Preview name="ai-messages-tool-ui" />

A function child of `AIMessageParts` that handles the same tool wins over the registered component.

### User bubble

The bubble of the user is only CSS, so there is no component to configure. The width is capped at `33.75rem`. Change the cap with `--sl-ai-message-user-max-width`:

```css
[data-sl-ai-messages] {
  --sl-ai-message-user-max-width: 28rem;
}
```

### Long threads

Each message row uses `content-visibility: auto`, so rows that are off screen cost nothing. Their placeholder height comes from `--sl-ai-message-intrinsic-size` (default `5rem`). `[data-sl-ai-message]` also has padding and a negative margin that cancel each other, so the content keeps its width and position, and focus rings and the reasoning button are not clipped by the row. The row box extends about `1rem` past the messages container, so a focus ring at the very edge is still clipped by an ancestor with `overflow: hidden`. The default spacing of the thread covers this, but only when `AIMessages` is a direct child of `AIThreadViewport` (the selector is `[data-sl-ai-thread-viewport] > [data-sl-ai-messages]`). If you wrap `AIMessages` in your own element, put `padding: var(--sl-ai-thread-padding, var(--sl-space-4))` on that wrapper, with `padding-bottom: var(--sl-ai-messages-gap, var(--sl-space-8))` for the last actions bar, so the composer stays aligned with the messages. Do not override `padding` or `margin` on the message row. See [AIThread](/components/ai-thread#long-conversations).

### Labels and languages

The labels come from a built-in catalog in `en-US` and `pt-BR`, chosen by the `LocaleProvider`. To change some of them for the whole chat, pass `messages` to `AIMessages`. Unset keys keep the default. To change the text of a single label, pass children to `AIMessageReasoningLabel`:

<Preview name="ai-messages-labels" />

| Id | `en-US` | Where it shows |
|----|---------|----------------|
| `reasoningStreaming` | Reasoning… | The label while the reasoning is running |
| `reasoningDone` | Reasoning complete | The label when it is complete and no duration is known |
| `reasoningDoneIn` | `Reasoning completed in {duration}` | The label when the duration is known. `{duration}` comes from `Intl` |
| `copyMessage` | Copy message | The name of the copy button |
| `copied` | Copied! | The name of the copy button for 2 seconds after a copy |
| `messageCopied` | Message copied | Announced to screen readers after a copy |
| `copyCode` | Copy code | Not used yet. It is kept for the code blocks |

### Where a customization lives

| You want to change | Use |
|--------------------|-----|
| A text for the whole chat | `messages` on `AIMessages` |
| The text of one reasoning label | Children of `AIMessageReasoningLabel` |
| The working mark | `workingMark` on `AIMessages` |
| The header pieces or their order | The `reasoning` template of `AIMessageParts` |
| Bar actions | Children of `AIMessageActions` |
| Language, dates and durations | `LocaleProvider` |

## Markdown

`AIMessageText` and the reasoning text draw their content with `AIMarkdown`, which supports GitHub-style markdown. You can use `AIMarkdown` alone for static content. Its rendering is documented here as it is today, and may be reworked later.

```tsx
<AIMarkdown>{'# Hello\n\nParagraph with **bold**.'}</AIMarkdown>
```

## Hooks

| Hook | Use it to |
|------|-----------|
| `useAIMessage()` | Read the `id`, `role`, `status` and `createdAt` of the message you are inside, for example to keep a vote per answer |
| `useAIMessageParts(messageId?)` | Read the parts of a message. Without an id, it reads the message you are inside |
| `useAIReasonings(messageId?)` | Read only the reasoning parts |
| `useAITools(messageId?)` | Read only the tool parts |
| `useAIResources(messageId?)` | Read only the files |
| `useAIThread()` | Read `messages` and call `sendMessage` or `loadMessages` |
| `useAIStatus()` | Know if the assistant is answering (`isStreaming`) |

## Breaking changes

These changes align the reasoning, the thinking indicator and the actions bar with the Design docs. The package is in beta, so they come with no deprecation period.

1. **`AIMessageAssistant` with children renders exactly the children.** It no longer adds the actions row or a thinking indicator around them. Add `AIMessageParts` and `AIMessageActions` yourself.
2. **`AIMessageActions` children replace the default actions.** Before, they came after the copy button. Now no children means copy and the date, and children are rendered alone, so include `AIMessageCopy` and `AIMessageDate` to keep them. The bar is always visible and floats below the message; the hover-only behavior is gone.
3. **`AIThinkingIndicator` is only the text effect.** The `label` prop is removed: pass the text as children. It is a `span` with no `role`, no dots and no default text.
4. **Reasoning is composed from parts.** `AIMessageReasoningTrigger` loses its `label` prop and is only the chevron, so clicking the label or the time no longer toggles the panel (the old trigger was the whole row). The text moves to `AIMessageReasoningLabel`, and `AIMessageReasoningHeader` is the row. The `[data-sl-ai-message-reasoning-row]`, `[data-sl-ai-message-reasoning-meta]` and `[data-sl-ai-dots-loader]` selectors are gone.
5. **Catalog keys changed.** `reasoningReady` is now `reasoningDone`, `workedFor` is now `reasoningDoneIn`, `thinking` is removed, and `copied` is new.
6. **`AIMessageCopy` and `AIMessageAction` take no `aria-label`.** The accessible name comes from the `label` prop of `AIMessageAction`, and from the built-in strings for `AIMessageCopy`.

The gap between messages also grows from 16px to 32px, and the thread now pads the messages and the composer. See [AIThread](/components/ai-thread#layout-and-spacing).
