# AIMessageDate

<ComponentDescription>When the message was sent, such as "now", "5m ago" or "yesterday, 2:32 PM". It is in the default actions bar; add it yourself when you pass children to AIMessageActions.</ComponentDescription>

```tsx
<AIMessageActions>
  <AIMessageCopy />
  <AIMessageDate />
</AIMessageActions>
```

It reads `createdAt` from the message, or takes a `date` prop, and renders nothing without a valid date. The text follows the locale of the `LocaleProvider` and comes from `Intl`: under a minute "now", under an hour the minutes ("5m ago"), later on the same day the time ("2:32 PM"), the previous calendar day "yesterday, 2:32 PM", and older dates "Nov 12, 2:32 PM", with the year when it is not the current one. In pt-BR the built-in catalog sets the format the design asks for: "há 5 min", "ontem, 14:32", "12 nov, 14:32". All the dates share one timer that ticks once a minute.

With server rendering, the text and the title appear after hydration, in the viewer's timezone.

## Optional props

<PropsDocs name="ai-message-date" />

`AIMessageDate` also accepts the props of a `time` element, except `dateTime` and `children`.

## Accessibility

- It is a `time` element: `dateTime` is the ISO value, and `title` is the exact local date and time.
- Only the "now" form is always visible. Any other date shows when you hover the message or when focus is inside it, so a keyboard user reaches it with <kbd>Tab</kbd>. On devices without hover it is always visible.

## Styling

| Attribute | Region |
|-----------|--------|
| `[data-sl-ai-message-date]` | The date, in `caption2` and `--sl-color-gray-6`. It has `data-just-now` under a minute, when it is always visible |
